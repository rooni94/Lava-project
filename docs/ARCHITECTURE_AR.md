# معمارية Lava

تشرح هذه الوثيقة المعمارية الموجودة في المصدر البرمجي، وتقتصر على سلوك التطبيق وطريقة التشغيل المحلية والحاويات. لا تتضمن بيانات اعتماد الإنتاج أو المضيفات الخاصة أو الشهادات أو بيانات العملاء.

## مكونات التشغيل

~~~mermaid
flowchart LR
    Browser[المتصفح] --> React[واجهة React/Vite]
    React --> Nginx[Nginx الواجهة]
    Nginx --> HTTP[Django وDRF]
    Nginx --> Socket[Channels وWebSocket]
    HTTP --> ORM[Django ORM]
    ORM --> DB[(PostgreSQL أو SQLite)]
    HTTP --> Cache[Redis أو Memcached أو الذاكرة المحلية]
    Socket --> Channel[قناة Redis أو الذاكرة]
    HTTP --> Storage[وسائط محلية أو S3 اختياري]
    Celery[عامل وجدولة Celery] --> Broker[وسيط Redis]
    Broker --> DB
~~~

## الواجهة الأمامية

الواجهة تطبيق React أحادي الصفحة مبني بواسطة Vite. يعلن App.tsx المسارات العامة ومسارات لوحة التحكم، ويستخدم PageGuard للتحقق من ظهور الصفحات عبر API. تعرض مكونات التخطيط المشتركة شريط التنقل والتذييل وودجت الدعم وتحميل المظهر والتحكم بالتمرير. يدير TanStack Query حالة الخادم وإبطال التخزين المؤقت بعد تعديلات لوحة التحكم، بينما يوفر i18next وreact-i18next المحتوى الثنائي اللغة والعرض الملائم للاتجاه.

تشارك صفحات لوحة التحكم في تخطيط موحد وتستخدم وحدة endpoints لعمليات CRUD. تشمل دورة الوسائط نافذة اختيار ونافذة قص ورفعًا ومعاينة Lightbox وحل روابط الوسائط. كما توجد أدوات محرر غني وحالات تحميل ورسائل Toast وحد لمعالجة الأخطاء.

## الخادم الخلفي

يوجد مشروع Django في backend/lava/. يجمع urls.py بين ViewSets المسجلة عبر Router وواجهات API الصريحة. يوجه asgi.py طلبات HTTP إلى Django وطلبات WebSocket إلى مسارات الدعم عبر وسيط يدعم JWT، بينما يوفر wsgi.py مدخل WSGI التقليدي.

تنقسم التطبيقات بحسب المسؤولية:

- core: إعدادات الموقع والصفحات والأقسام وبيانات التواصل والطلبات والوسائط وسجل النشاط والتقييد والأدوات المشتركة.
- accounts: نموذج المستخدم والأدوار وتسجيل JWT وتدفقات كلمات المرور وواجهات المستخدمين.
- services وpackages وportfolio: الخدمات والباقات ومحتوى الأعمال.
- blog وclients وteam وcareers: المدونة والعملاء وأعضاء الفريق والتوظيف.
- support: المحادثات والتحقق من الزوار ورسائل الدعم ونشاط الموظفين والأتمتة والمستهلكات اللحظية.
- dashboard: الإحصاءات المجمعة وواجهات الرفع التي تستخدمها لوحة التحكم.

## تدفق الطلب

1. يحمل المتصفح تطبيق Vite المبني من خلال Nginx.
2. يستدعي React Query عميل Axios للحصول على الموارد العامة أو المحمية.
3. يمرر Nginx مسارات /api/ إلى Django HTTP ومسارات /ws/ إلى WebSocket في ASGI.
4. يصادق DRF طلبات JWT ويطبق صلاحيات القراءة العامة أو الصلاحيات المرتبطة بالدور.
5. تتحقق ViewSets من المدخلات عبر serializers، ثم تستخدم Django ORM، ويسجل خلط النشاط تعديلات لوحة التحكم حيث يكون مستخدمًا.
6. تستخدم إشعارات البريد والنشر المجدول والتخزين المؤقت والبث اللحظي الخدمات المضبوطة عند تفعيلها.

## المصادقة والصلاحيات

يستخدم API رموز Simple JWT للوصول والتجديد. يضيف accounts.User الأدوار super_admin وmanager وeditor وviewer. تجمع RolePermission منطق صلاحيات الكتابة، بينما تخصص الواجهات صلاحيات الإرسال العام والقراءة للمستخدمين المسجلين وعمليات موظفي الدعم. تستخدم استعادة كلمة المرور مولد Django للرموز وأدوات البريد.

## البيانات والتخزين

يحتوي المستودع على migrations وأصول عامة ثابتة متعقبة، ولا يحتوي قاعدة بيانات. تُستخدم PostgreSQL عند ضبط DATABASE_URL، وإلا يستخدم Django ملف SQLite متجاهلًا في التطوير. تحفظ الوسائط عبر طبقة التخزين في Django، مع التحقق من الصور وتغيير حجمها وإخراج WebP وإضافة علامة مائية نصية أو شعار عند الحاجة. لا يُفعل S3 إلا عند ضبط USE_S3=True وتوفير بياناته خارج Git.

## التخزين المؤقت وCelery والوقت الحقيقي

يمكن لـ Redis تشغيل التخزين المؤقت في Django وChannels وCelery. عند غياب Redis، توفر الإعدادات تخزينًا مؤقتًا في الذاكرة وقناة Channels داخلية للتطوير. يكتشف Celery المهام من التطبيقات ويجدول فحوص نشر مقالات المدونة ومشاريع الأعمال. تبث مستهلكات Channels رسائل الدعم إلى مجموعات المحادثات وتحفظ الرسائل وحالات القراءة والنشاط عبر نماذج Django.

## Docker ومسار النشر

يشغل Compose التطويري PostgreSQL وRedis وخادم backend عبر Daphne وحاوية Nginx للواجهة. يمرر Nginx مسارات API والوسائط والملفات الثابتة وWebSocket إلى خدمة backend، ما يسمح للمتصفح باستخدام مسارات من نفس المصدر.

يضيف ملف Compose ذي التوجه الإنتاجي خدمة Nginx عكسية وربط وحدات الشهادات وخدمة Certbot. المسارات نسبية، وقيم قاعدة البيانات وكلمات المرور تمرر عبر متغيرات البيئة. ملف deploy/nginx/conf.d/default.conf إعداد HTTP تجريبي للتقييم؛ أما شهادات TLS وإعداد الخادم الخاص بالإنتاج فتبقى مسؤولية المشغّل وليست ضمن المستودع.

## حدود الأمان

لا تتضمن نسخة العرض ملف .env أو قاعدة إنتاج أو dump أو لقطة Redis أو نسخة احتياطية أو مفتاحًا خاصًا أو رفعًا خاصًا أو بيانات اعتماد للبنية التحتية. يجب إنشاء أسرار التشغيل أو تمريرها خارج Git. ملفات migrations كود للمخطط وليست بيانات إنتاج.
